Triggers - إيه هي وامتى تستخدمها

هتتعلم إيه هو الـ Trigger، أنواعه، وإزاي تخلي الداتابيز تتصرف تلقائياً لما حاجة تحصل - بدون ما تتدخل!

المقدمة

إيه هو الـ Trigger؟

🔔

تشبيه: جرس الباب!

الـ Trigger زي جرس الباب بالظبط: لما حد يدوس عليه (حدث يحصل على الجدول - INSERT/UPDATE/DELETE)، الجرس بيرن تلقائياً (الكود بيشتغل لوحده). إنت مش محتاج تفضل تراقب الباب - الجرس هيعرفك تلقائياً!

الـ Trigger هو كود PL/SQL بيشتغل تلقائياً لما حدث معين يحصل على جدول معين. مش بتستدعيه بإيدك - هو بيشتغل لوحده!

مربوط بحدث

INSERT أو UPDATE أو DELETE

PL/SQL - الصيغة العامة
CREATE OR REPLACE TRIGGER trigger_name
BEFORE | AFTER
INSERT | UPDATE | DELETE
ON table_name
[FOR EACH ROW]
BEGIN
    -- الكود اللي هيشتغل تلقائياً
END;
/
الأنواع

BEFORE vs AFTER

كل Trigger لازم تحدد: هيشتغل قبل العملية ولا بعدها؟

⏪ BEFORE Trigger

  • بيشتغل قبل ما العملية تتنفذ
  • تقدر تعدّل البيانات قبل ما تتحفظ
  • تقدر تمنع العملية بـ RAISE_APPLICATION_ERROR
  • مثال: تعبي created_date تلقائياً
  • مثال: تتحقق من بيانات قبل ما تتحفظ
VS

⏩ AFTER Trigger

  • بيشتغل بعد ما العملية تتنفذ
  • مش تقدر تعدل البيانات (خلاص اتحفظت!)
  • بيستخدم للـ logging و auditing
  • مثال: تسجل في audit log
  • مثال: تبعت notification
القاعدة: لو عايز تعدّل أو تمنع = BEFORE. لو عايز تسجّل أو تراقب = AFTER.
الأحداث

INSERT / UPDATE / DELETE Events

الـ Trigger بيشتغل لما حدث معين يحصل. تقدر تربطه بحدث واحد أو أكتر:

➕

INSERT

لما صف جديد يتضاف للجدول

✏️

UPDATE

لما بيانات صف موجود تتعدّل

🗑️

DELETE

لما صف يتمسح من الجدول

PL/SQL - حدث واحد
-- Trigger على INSERT بس
CREATE OR REPLACE TRIGGER trg_after_insert
AFTER INSERT ON employees
FOR EACH ROW
BEGIN
    DBMS_OUTPUT.PUT_LINE('تم إضافة موظف جديد!');
END;
/
PL/SQL - أحداث متعددة
-- Trigger على أكتر من حدث
CREATE OR REPLACE TRIGGER trg_emp_changes
AFTER INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW
BEGIN
    IF INSERTING THEN
        DBMS_OUTPUT.PUT_LINE('تم إضافة موظف');
    ELSIF UPDATING THEN
        DBMS_OUTPUT.PUT_LINE('تم تعديل موظف');
    ELSIF DELETING THEN
        DBMS_OUTPUT.PUT_LINE('تم حذف موظف');
    END IF;
END;
/
✅ ملحوظة: INSERTING و UPDATING و DELETING هي conditional predicates بتقولك أنهي عملية اللي حصلت.
المستوى

ROW-level vs STATEMENT-level

📝 STATEMENT-level

  • بيشتغل مرة واحدة لكل أمر SQL
  • مش بنكتب FOR EACH ROW
  • مش بيقدر يوصل لـ :NEW و :OLD
  • لو عملت UPDATE لـ 100 صف = الـ Trigger بيشتغل مرة واحدة بس
VS

📋 ROW-level (FOR EACH ROW)

  • بيشتغل مرة لكل صف متأثر
  • بنكتب FOR EACH ROW
  • بيقدر يوصل لـ :NEW و :OLD
  • لو عملت UPDATE لـ 100 صف = الـ Trigger بيشتغل 100 مرة!
PL/SQL - الفرق
-- STATEMENT-level (مرة واحدة)
CREATE OR REPLACE TRIGGER trg_stmt_level
AFTER UPDATE ON employees
-- بدون FOR EACH ROW
BEGIN
    DBMS_OUTPUT.PUT_LINE('حصل تعديل على جدول الموظفين');
END;
/

-- ROW-level (مرة لكل صف)
CREATE OR REPLACE TRIGGER trg_row_level
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    DBMS_OUTPUT.PUT_LINE('تم تعديل موظف: ' || :OLD.first_name);
END;
/
خلاصة: أغلب الـ Triggers بتكون ROW-level (FOR EACH ROW) عشان محتاج توصل لبيانات كل صف.
البيانات

:NEW و :OLD - Pseudo-Records

في ROW-level Trigger، تقدر توصل للبيانات القديمة والبيانات الجديدة لكل صف:

جدول المقارنة:

العملية:OLD:NEW
INSERT❌ NULL (مفيش بيانات قديمة)✅ البيانات الجديدة اللي هتتضاف
UPDATE✅ البيانات قبل التعديل✅ البيانات بعد التعديل
DELETE✅ البيانات اللي هتتمسح❌ NULL (مفيش بيانات جديدة)
PL/SQL - استخدام :NEW و :OLD
CREATE OR REPLACE TRIGGER trg_salary_change
AFTER UPDATE OF salary ON employees
FOR EACH ROW
BEGIN
    DBMS_OUTPUT.PUT_LINE(
        'الموظف: ' || :OLD.first_name ||
        ' - المرتب القديم: ' || :OLD.salary ||
        ' - المرتب الجديد: ' || :NEW.salary
    );
END;
/
⚠️ مهم: في BEFORE trigger تقدر تعدّل :NEW (مثلاً :NEW.salary := 5000). لكن في AFTER trigger مش تقدر تعدّل لأن البيانات خلاص اتحفظت!
تطبيق عملي

أول Trigger: تسجيل في Audit Log

هنعمل جدول audit_log عشان نسجل فيه كل عملية حذف تحصل على جدول الموظفين.

الخطوة 1: إنشاء جدول الـ Audit Log

SQL - CREATE TABLE
CREATE TABLE audit_log (
    audit_id     NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    table_name   VARCHAR2(50),
    operation    VARCHAR2(10),
    old_data     VARCHAR2(500),
    changed_by   VARCHAR2(50),
    changed_date DATE DEFAULT SYSDATE
);

الخطوة 2: إنشاء الـ Trigger

PL/SQL - AFTER DELETE Trigger
CREATE OR REPLACE TRIGGER trg_audit_emp_delete
AFTER DELETE ON employees
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, operation, old_data, changed_by)
    VALUES (
        'EMPLOYEES',
        'DELETE',
        'ID=' || :OLD.employee_id ||
        ', Name=' || :OLD.first_name ||
        ', Salary=' || :OLD.salary,
        USER
    );
END;
/

-- جرّب:
DELETE FROM employees WHERE employee_id = 999;

-- شوف الـ audit log:
SELECT * FROM audit_log;
✅ كده: كل مرة حد يحذف موظف، الـ Trigger هيسجل التفاصيل تلقائياً في جدول الـ audit_log. محدش يقدر يحذف من غير ما يتسجل!
BEFORE INSERT

BEFORE INSERT: تعبئة بيانات تلقائياً

أشهر استخدام للـ BEFORE INSERT هو تعبئة بيانات تلقائياً قبل ما الصف يتحفظ:

PL/SQL - Auto-fill defaults
CREATE OR REPLACE TRIGGER trg_emp_defaults
BEFORE INSERT ON employees
FOR EACH ROW
BEGIN
    -- تعبئة تاريخ الإنشاء تلقائياً
    :NEW.hire_date := SYSDATE;

    -- لو المرتب فاضي، حط قيمة افتراضية
    IF :NEW.salary IS NULL THEN
        :NEW.salary := 3000;
    END IF;

    -- خلي الاسم يبدأ بحرف كبير
    :NEW.first_name := INITCAP(:NEW.first_name);
    :NEW.last_name  := INITCAP(:NEW.last_name);
END;
/

-- جرّب:
INSERT INTO employees (employee_id, first_name, last_name, email, job_id)
VALUES (999, 'ahmed', 'mohamed', 'AHMEDM', 'IT_PROG');

-- شوف النتيجة - hire_date اتملت و salary = 3000 و الاسم بحرف كبير!
SELECT first_name, last_name, hire_date, salary
FROM employees WHERE employee_id = 999;
الفكرة: الـ BEFORE INSERT بيديك فرصة تتحكم في البيانات قبل ما تتحفظ. تقدر تعدّل :NEW بحرية!
BEFORE UPDATE

BEFORE UPDATE: منع تقليل المرتب

هنا الـ Trigger بيشتغل كـ حارس - بيمنع أي تعديل غلط:

PL/SQL - Validation Trigger
CREATE OR REPLACE TRIGGER trg_prevent_salary_decrease
BEFORE UPDATE OF salary ON employees
FOR EACH ROW
BEGIN
    -- لو المرتب الجديد أقل من القديم = ارفض!
    IF :NEW.salary < :OLD.salary THEN
        RAISE_APPLICATION_ERROR(
            -20001,
            'ممنوع تقلّل المرتب! القديم: ' || :OLD.salary ||
            ' الجديد: ' || :NEW.salary
        );
    END IF;
END;
/

-- جرّب - ده هينجح:
UPDATE employees SET salary = salary + 500
WHERE employee_id = 100;

-- جرّب - ده هيفشل!
UPDATE employees SET salary = 1000
WHERE employee_id = 100;
-- ORA-20001: ممنوع تقلّل المرتب!
🚨 RAISE_APPLICATION_ERROR: دي الطريقة عشان تمنع العملية وترجع رسالة خطأ. الرقم لازم يكون بين -20000 و -20999.
PL/SQL - مثال تاني: منع التعديل في الأجازات
CREATE OR REPLACE TRIGGER trg_no_weekend_changes
BEFORE UPDATE ON employees
FOR EACH ROW
BEGIN
    IF TO_CHAR(SYSDATE, 'DY') IN ('FRI', 'SAT') THEN
        RAISE_APPLICATION_ERROR(
            -20002,
            'ممنوع التعديل في أيام الأجازة!'
        );
    END IF;
END;
/
AFTER INSERT

AFTER INSERT: تسجيل الإضافات

بعد ما الموظف الجديد يتضاف بنجاح، نسجل العملية دي:

PL/SQL - Logging Trigger
CREATE OR REPLACE TRIGGER trg_log_new_employee
AFTER INSERT ON employees
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, operation, old_data, changed_by)
    VALUES (
        'EMPLOYEES',
        'INSERT',
        'New ID=' || :NEW.employee_id ||
        ', Name=' || :NEW.first_name || ' ' || :NEW.last_name ||
        ', Salary=' || :NEW.salary,
        USER
    );
END;
/

-- جرّب:
INSERT INTO employees (employee_id, first_name, last_name, email, hire_date, job_id, salary)
VALUES (998, 'Sara', 'Ali', 'SARAA', SYSDATE, 'IT_PROG', 7000);

-- شوف الـ log:
SELECT * FROM audit_log WHERE operation = 'INSERT';
PL/SQL - تسجيل تعديل المرتبات
CREATE OR REPLACE TRIGGER trg_log_salary_change
AFTER UPDATE OF salary ON employees
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, operation, old_data, changed_by)
    VALUES (
        'EMPLOYEES',
        'UPDATE',
        'EmpID=' || :OLD.employee_id ||
        ' OldSalary=' || :OLD.salary ||
        ' NewSalary=' || :NEW.salary,
        USER
    );
END;
/
الإدارة

إدارة Triggers

تعطيل وتفعيل Trigger

SQL - ENABLE / DISABLE
-- تعطيل Trigger واحد
ALTER TRIGGER trg_prevent_salary_decrease DISABLE;

-- تفعيل Trigger واحد
ALTER TRIGGER trg_prevent_salary_decrease ENABLE;

-- تعطيل كل Triggers على جدول معين
ALTER TABLE employees DISABLE ALL TRIGGERS;

-- تفعيل كل Triggers على جدول معين
ALTER TABLE employees ENABLE ALL TRIGGERS;

حذف Trigger

SQL - DROP TRIGGER
DROP TRIGGER trg_prevent_salary_decrease;

عرض كل الـ Triggers

SQL - عرض من user_triggers
-- كل الـ Triggers الخاصة بيك
SELECT trigger_name, trigger_type, triggering_event,
       table_name, status
FROM user_triggers;

-- Triggers على جدول معين
SELECT trigger_name, trigger_type, triggering_event, status
FROM user_triggers
WHERE table_name = 'EMPLOYEES';

-- كود الـ Trigger
SELECT trigger_body
FROM user_triggers
WHERE trigger_name = 'TRG_PREVENT_SALARY_DECREASE';

أهم أعمدة user_triggers:

العمودالوصف
TRIGGER_NAMEاسم الـ Trigger
TRIGGER_TYPEBEFORE/AFTER + EACH ROW/STATEMENT
TRIGGERING_EVENTINSERT / UPDATE / DELETE
TABLE_NAMEالجدول المرتبط بيه
STATUSENABLED أو DISABLED
TRIGGER_BODYكود الـ Trigger
نصائح

أفضل الممارسات

📏

خليه قصير

الـ Trigger لازم يكون قصير وبسيط. لو الكود طويل، حطه في Procedure واستدعيها

🚫

لا COMMIT جواه

ممنوع COMMIT أو ROLLBACK جوه الـ Trigger! هو جزء من الـ transaction الأصلية

⛓️

تجنب التسلسل

لا تخلي Trigger يعمل عملية تشغّل Trigger تاني (cascading) - ده بيسبب مشاكل

🚨 أخطاء شائعة:
  • كتابة COMMIT جوه الـ Trigger = ORA-04092
  • الـ Trigger بيعمل UPDATE على نفس الجدول = ORA-04091 (Mutating Table)
  • Trigger بيشغّل Trigger تاني بيشغّل التالت = infinite loop محتمل!
⚠️ Mutating Table Error: لو الـ ROW-level Trigger حاول يعمل SELECT أو UPDATE على نفس الجدول اللي الـ Trigger عليه = خطأ ORA-04091. الحل: استخدم STATEMENT-level trigger أو compound trigger.

قواعد ذهبية:

القاعدةالسبب
خلي الـ Trigger قصيرالأداء - الـ Trigger بيشتغل مع كل عملية
لا COMMIT / ROLLBACKالـ Trigger جزء من الـ transaction
تجنب cascading triggersصعب الـ debugging وممكن يسبب infinite loop
استخدم naming conventionمثلاً: trg_before_insert_emp
وثّق الـ Triggerاكتب comments توضح ليه الـ Trigger موجود
لا تستخدمه لـ business logic معقداستخدم Procedures بدل كده
تمارين

تمارين عملية

تمرين 1: Trigger بسيط للطباعة

سهل

اكتب AFTER INSERT Trigger على جدول employees بيطبع "مرحباً بالموظف الجديد!" مع اسم الموظف.

استخدم :NEW.first_name عشان توصل لاسم الموظف الجديد، و DBMS_OUTPUT.PUT_LINE للطباعة.

PL/SQL
CREATE OR REPLACE TRIGGER trg_welcome_emp
AFTER INSERT ON employees
FOR EACH ROW
BEGIN
    DBMS_OUTPUT.PUT_LINE(
        'مرحباً بالموظف الجديد: ' || :NEW.first_name
    );
END;
/

تمرين 2: Auto-fill تاريخ التعيين

سهل

اكتب BEFORE INSERT Trigger على employees بيملأ hire_date بالتاريخ الحالي لو كانت فاضية.

استخدم IF :NEW.hire_date IS NULL THEN وبعدها :NEW.hire_date := SYSDATE;

PL/SQL
CREATE OR REPLACE TRIGGER trg_auto_hire_date
BEFORE INSERT ON employees
FOR EACH ROW
BEGIN
    IF :NEW.hire_date IS NULL THEN
        :NEW.hire_date := SYSDATE;
    END IF;
END;
/

تمرين 3: منع حذف المديرين

متوسط

اكتب BEFORE DELETE Trigger على employees بيمنع حذف أي موظف job_id بتاعه 'AD_PRES' أو 'AD_VP'.

استخدم :OLD.job_id IN ('AD_PRES', 'AD_VP') و RAISE_APPLICATION_ERROR.

PL/SQL
CREATE OR REPLACE TRIGGER trg_protect_managers
BEFORE DELETE ON employees
FOR EACH ROW
BEGIN
    IF :OLD.job_id IN ('AD_PRES', 'AD_VP') THEN
        RAISE_APPLICATION_ERROR(
            -20003,
            'ممنوع حذف المديرين! الموظف: ' || :OLD.first_name
        );
    END IF;
END;
/

تمرين 4: تسجيل تعديلات المرتب

متوسط

اعمل جدول salary_history (emp_id, old_salary, new_salary, change_date) واكتب AFTER UPDATE Trigger بيسجل كل تعديل مرتب فيه.

اعمل الجدول الأول بـ CREATE TABLE، وبعدين اكتب AFTER UPDATE OF salary Trigger بيعمل INSERT في الجدول الجديد.

PL/SQL
CREATE TABLE salary_history (
    history_id   NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    emp_id       NUMBER,
    old_salary   NUMBER,
    new_salary   NUMBER,
    change_date  DATE DEFAULT SYSDATE
);

CREATE OR REPLACE TRIGGER trg_salary_history
AFTER UPDATE OF salary ON employees
FOR EACH ROW
BEGIN
    INSERT INTO salary_history (emp_id, old_salary, new_salary)
    VALUES (:OLD.employee_id, :OLD.salary, :NEW.salary);
END;
/

تمرين 5: Trigger بأحداث متعددة

متوسط

اكتب Trigger على employees بيشتغل على INSERT و UPDATE و DELETE وبيسجل نوع العملية في audit_log باستخدام INSERTING و UPDATING و DELETING.

استخدم IF INSERTING THEN ... ELSIF UPDATING THEN ... ELSIF DELETING THEN ... جوه الـ Trigger.

PL/SQL
CREATE OR REPLACE TRIGGER trg_all_emp_changes
AFTER INSERT OR UPDATE OR DELETE ON employees
FOR EACH ROW
DECLARE
    v_operation VARCHAR2(10);
    v_details   VARCHAR2(500);
BEGIN
    IF INSERTING THEN
        v_operation := 'INSERT';
        v_details := 'New: ' || :NEW.first_name || ' Sal=' || :NEW.salary;
    ELSIF UPDATING THEN
        v_operation := 'UPDATE';
        v_details := 'Old=' || :OLD.salary || ' New=' || :NEW.salary;
    ELSIF DELETING THEN
        v_operation := 'DELETE';
        v_details := 'Deleted: ' || :OLD.first_name;
    END IF;

    INSERT INTO audit_log (table_name, operation, old_data, changed_by)
    VALUES ('EMPLOYEES', v_operation, v_details, USER);
END;
/

تمرين 6: منع زيادة المرتب أكتر من 50%

صعب

اكتب BEFORE UPDATE Trigger على employees بيمنع زيادة المرتب لو الزيادة أكتر من 50% من المرتب الأصلي.

قارن :NEW.salary مع :OLD.salary * 1.5. لو أكبر، ارفض بـ RAISE_APPLICATION_ERROR.

PL/SQL
CREATE OR REPLACE TRIGGER trg_limit_raise
BEFORE UPDATE OF salary ON employees
FOR EACH ROW
BEGIN
    IF :NEW.salary > :OLD.salary * 1.5 THEN
        RAISE_APPLICATION_ERROR(
            -20004,
            'ممنوع زيادة المرتب أكتر من 50%! القديم: ' ||
            :OLD.salary || ' الحد الأقصى: ' ||
            :OLD.salary * 1.5
        );
    END IF;
END;
/

تمرين 7: Trigger لتحويل البريد لحروف كبيرة

صعب

اكتب BEFORE INSERT OR UPDATE Trigger على employees بيحوّل الـ email لحروف كبيرة تلقائياً ويتأكد إنه مش NULL.

استخدم :NEW.email := UPPER(:NEW.email) واتحقق بـ IF :NEW.email IS NULL THEN RAISE_APPLICATION_ERROR.

PL/SQL
CREATE OR REPLACE TRIGGER trg_email_format
BEFORE INSERT OR UPDATE OF email ON employees
FOR EACH ROW
BEGIN
    IF :NEW.email IS NULL THEN
        RAISE_APPLICATION_ERROR(
            -20005,
            'البريد الإلكتروني مطلوب!'
        );
    END IF;

    :NEW.email := UPPER(:NEW.email);
END;
/

تمرين 8: Trigger شامل - نظام Audit كامل

تحدي

اعمل جدول full_audit فيه (audit_id, table_name, operation, column_changed, old_value, new_value, changed_by, changed_date). واكتب AFTER UPDATE Trigger على employees بيسجل بالتفصيل أي عمود اتغيّر (salary, job_id, department_id).

اعمل الجدول الأول. في الـ Trigger، اعمل 3 شروط IF: واحد لـ salary، واحد لـ job_id، وواحد لـ department_id. كل واحد يعمل INSERT لو العمود اتغيّر.

PL/SQL
CREATE TABLE full_audit (
    audit_id       NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    table_name     VARCHAR2(50),
    operation      VARCHAR2(10),
    column_changed VARCHAR2(50),
    old_value      VARCHAR2(200),
    new_value      VARCHAR2(200),
    changed_by     VARCHAR2(50),
    changed_date   DATE DEFAULT SYSDATE
);

CREATE OR REPLACE TRIGGER trg_full_audit_emp
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    -- تسجيل تغيير المرتب
    IF :OLD.salary != :NEW.salary THEN
        INSERT INTO full_audit
            (table_name, operation, column_changed, old_value, new_value, changed_by)
        VALUES ('EMPLOYEES', 'UPDATE', 'SALARY',
            TO_CHAR(:OLD.salary), TO_CHAR(:NEW.salary), USER);
    END IF;

    -- تسجيل تغيير الوظيفة
    IF :OLD.job_id != :NEW.job_id THEN
        INSERT INTO full_audit
            (table_name, operation, column_changed, old_value, new_value, changed_by)
        VALUES ('EMPLOYEES', 'UPDATE', 'JOB_ID',
            :OLD.job_id, :NEW.job_id, USER);
    END IF;

    -- تسجيل تغيير القسم
    IF NVL(:OLD.department_id, 0) != NVL(:NEW.department_id, 0) THEN
        INSERT INTO full_audit
            (table_name, operation, column_changed, old_value, new_value, changed_by)
        VALUES ('EMPLOYEES', 'UPDATE', 'DEPARTMENT_ID',
            TO_CHAR(:OLD.department_id), TO_CHAR(:NEW.department_id), USER);
    END IF;
END;
/

ملخص اللي اتعلمناه

  • الـ Trigger كود PL/SQL بيشتغل تلقائياً لما حدث يحصل على جدول
  • BEFORE = قبل العملية (للتعديل والمنع) / AFTER = بعد العملية (للتسجيل)
  • الأحداث: INSERT / UPDATE / DELETE أو مجموعة منهم
  • FOR EACH ROW = مرة لكل صف / بدونها = مرة لكل أمر SQL
  • :NEW = البيانات الجديدة / :OLD = البيانات القديمة
  • RAISE_APPLICATION_ERROR لمنع العملية وإرجاع رسالة خطأ
  • ALTER TRIGGER لتعطيل/تفعيل / DROP TRIGGER للحذف
  • خلي الـ Trigger قصير، ولا تستخدم COMMIT جواه، وتجنب cascading
